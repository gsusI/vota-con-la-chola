# Issue seeds

Estos archivos son borradores listos para convertirse en issues reales de GitHub.

Uso recomendado:

1. elegir el seed que corresponda al siguiente paso real,
2. abrir un issue usando el titulo, contexto y DoD del seed,
3. ajustar labels, responsables y milestone segun capacidad actual,
4. enlazar el issue desde PRs y release notes cuando aplique.

## Reglas

- Los seeds no son backlog operativo vivo; el estado real sigue en `docs/etl/e2e-scrape-load-tracker.md` y `docs/roadmap-tecnico.md`.
- Los labels sugeridos siguen la taxonomia de `docs/ops/github-about.md`.
- Si un seed cambia el alcance publico o el contrato de datos, registrar decision en `docs/governance/decision-log-process.md`.
